# Soma

Runner Windows nativo en Rust. GUI y CLI comparten una única autoridad de ejecución mediante IPC local. Usá `soma-cli help` y sus respuestas JSON para operar la app.

Compartí el dueño y la cola usando el directorio de datos habitual; reservá `--data-dir` para entornos que requieren aislamiento. La CLI inicia dueños temporales sin interfaz y los cierra cuando ya no hay aplicación ni trabajos pendientes. `show` abre la interfaz del mismo dueño y la conserva hasta un cierre explícito. Al terminar tu tarea, detené las ejecuciones que iniciaste si ya no se necesitan y retirá tus participaciones pendientes. Conservá las ejecuciones, participaciones e interfaces ajenas. Los resultados finales siguen disponibles con sus IDs después del cierre; distinguí evidencia histórica de una aplicación actualmente disponible.

Desde un agente aislado en Windows, ejecutá los comandos Soma que usan IPC mediante el mecanismo de ejecución autorizada del anfitrión (en Codex, `exec_command` con `sandbox_permissions:"require_escalated"` para el comando exacto). También `status`, `logs` y consultas de jobs escriben una solicitud al canal del dueño. Un token de integridad baja puede recibir `access_denied`/`os_error:5` frente a un dueño de integridad media aunque el usuario sea el mismo. Usá la aprobación normal del anfitrión y verificá el resultado JSON; esta instrucción no concede permisos adicionales. Conservá los IDs y las reglas de propiedad. La recuperación no requiere cambiar ACLs ni cerrar el dueño.

`model.rs` posee configuración, entorno y vigencia de builds; `owner.rs`, autoridad única y ciclo de vida temporal/interactivo; `engine.rs`, operaciones, resultados finales, logs y árboles de procesos; `observation.rs`, atribución y cursores de logs; `jobs.rs`, cola, participaciones y resultados; `reports.rs`, evidencia Surefire/Failsafe; `jobs_cli.rs`, comandos de trabajos; `worker.rs`, consola y Ctrl+C; `ipc.rs`, protocolo; `ui.rs`, controles Win32. Conservá las colas acotadas y el control de reentrada del visor. [GLOSSARY.md](GLOSSARY.md) define el dominio.

`job_output.rs` mantiene veredictos y resúmenes; `job_history.rs`, el archivo acotado de metadata; `test_profiles.rs`, preflight y clonado de configuraciones de pruebas. Para consultar muchos trabajos usá `--summary` en `jobs list`, `jobs status` y `jobs wait`; para diagnosticar, continuá `jobs logs --job ID` con su cursor. [CLI.md](CLI.md#trabajos-maven-independientes) define filtros, veredictos, exportación y configuración aislada. Ejecutá `wait` en una sesión no bloqueante del anfitrión y conservá su ID de terminal; evitá repetir esperas de un segundo y el mismo tail.

Para levantar una aplicación, elegí el checkout con `run --path DIRECTORIO`, guardá el `operation_id` y usá `wait --operation ID --ready` para comprobar disponibilidad. Detené únicamente la ejecución que iniciás mediante `stop --operation ID`. `--wait` sigue esperando la finalización del proceso. Consultá README para readiness, variables explícitas y selección de rama/worktree. Las pruebas y compilaciones específicas conservan sus herramientas y políticas locales.

Para diagnosticar una ejecución, usá `logs --operation ID` y conservá su cursor con el mismo alcance. `status --operation ID --health` consulta ahora el endpoint propio; readiness de arranque e historial no prueban salud actual. `cursor_expired` exige una lectura nueva. [CLI.md](CLI.md) documenta estados, filtros, retención y errores.

Para tests y compilaciones finitas de proyectos Maven registrados usá `jobs submit --path DIRECTORIO --config tests --kind test|build -- ARGUMENTOS_MAVEN`. Conservá `job_id` y `participant_id`, consultá `jobs wait/status/logs` y retirate con `jobs release --job ID --participant ID`. No canceles participaciones de otros. Un timeout no cancela; no cierres una ventana compartida para cancelar tu trabajo. `jobs status ok:true` solo confirma la consulta; validá el resultado de `jobs wait` y su evidencia. Los trabajos siguen usando el Wrapper y el adaptador configurado. Revisá el entorno separado de `test_configs`, sus proveedores y el alcance de los tests antes de enviarlos. Si hay política local de recursos, mantené el adaptador que la aplica y evitá launchers anidados.

Antes de enviar tests con una configuración nueva, usá `jobs doctor --path DIRECTORIO --config ID`. Para otra selección de proveedores, `jobs config-clone` crea un ID nuevo y puede preparar un directorio de datos aislado conservando el adaptador; no edites ni copies configuraciones de ejecución para suplir una configuración de tests. El preflight no sustituye las pruebas ni confirma compatibilidad del proveedor.

La precedencia de variables de ejecución es sistema → `.env` → overrides explícitos. Las pruebas usan su propia configuración; no heredan automáticamente el `.env` ni los parámetros JVM del runtime. Los datos personales viven en `%USERPROFILE%\.soma`, salvo configuración portable existente, `SOMA_HOME` o `--data-dir`. Conservá entradas ajenas al editar `projects.json`; ejecutá `validate` después. Para compartir presets JVM, preparar otra PC o compilar desde un clon, consultá `docs/portability.md` (`PORTABILITY.md` en el ZIP). `snapshot:true` solo corresponde a JAR autocontenido; no aísla bases de datos, archivos externos ni puertos.

Para validar cambios de ejecución, `tests/verify.ps1` ejercita la CLI con JVMs reales descartables. `tests/targets.ps1` verifica worktrees, cambios de rama, IDs de ejecución y readiness contra servidores Java reales. `tests/jobs.ps1` verifica coordinación, evidencia y cierre con Maven/JUnit reales. `tests/distribution.ps1` verifica almacenamiento entre versiones y el ZIP público. `cargo test` protege lectura de evidencia XML adversa. Respetá los controles de recursos de la máquina local; CI compila y prueba de forma secuencial.

Para publicar, leé `docs/releases.md`. El bundle usa una lista explícita de archivos, incluido el preset JVM público; perfiles personales, `.env`, logs, adaptadores personales y datos de usuarios quedan fuera. La versión se declara en `Cargo.toml` y su entrada de `Cargo.lock`. El tag debe coincidir con ella.
